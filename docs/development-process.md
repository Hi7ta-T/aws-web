## 開発フロー
2026年3月から検討開始。<br>
2026年4月にGitHubで成果物管理を始めてからは構築状況に応じて継続修正を行っている。<br>
<br>
以下、本成果物の開発フローを記載。
1. アプリケーションの目的・要件を整理<br>
構築する期間や範囲、どのような知識が必要になるかを調査。
2. 採用するクラウド、リソースを選定<br>
作成軸に対して何を選定するか、トレードオフを考慮しながら選定を実施。
3. NW構成を設計<br>
アプリケーションの規模やセキュリティ面を考慮し、SubnetやCIDRを設計。
4. 各リソースの選定理由について整理<br>
今回のアプリケーションで採用したリソースについて、他のリソースや技術と比較しながらドキュメント化。
5. 障害範囲別の運用設計を検討<br>
アプリケーションの運用について、障害の検知方法や発生時の対応、今後の改善案を記載。
6. 使用技術の整理、アーキテクチャ図の作成<br>
使用している技術スタックについて整理。アーキテクチャ図を作成し、アプリケーションの通信構造を可視化した。
7.TerraformによるVPC内リソースのIaC化<br>
terraform validate / fmt の実行後、追加ツールとしてTFLintを使用してセルフレビューを実施。
8. MySQLを用いたDB構築<br>
エンティティやカラムを整理し、ER図を作成。テーブルの作成後にDMLでサンプルデータを格納した。
**9. Fast API によるREST API実装**<br>
疎通検証のため、口コミ一覧取得(GET, /reviews)を先に実装。その後、必要となるAPIを実装する予定。
10. リソースの疎通検証実施<br>
各リソースの疎通検証を実施予定。HTTPS通信を行う箇所はCloudflareで取得したドメインをRoute 53へ移行した。
12. フロントエンドの実装<br>
HTML, CSS, JavaSchiptを用いてフロントエンドを作成予定。
13. 作成軸を考慮した設計改善<br>
疎通検証を優先して作成軸に背いてけっていしたかしのがあふため、作成軸を考慮したリソースへと設計を変更する。
